# 真实公共问答评估与质量修复（2026-09-15）

本轮继续 [Z11 #168](https://github.com/Bayashat/zerde-serverless-bot/issues/168)。目标仍是准确、有来源、可更正和遗忘的个人档案；学习保持 STOPPED，自动社交保持退役。测试、模型观测、实际部署与七天试运行分别验收。

## 本轮发现与实现

冻结的真实 Gemini 基线使用未改动的 240 场景、四语言 gold。完整 kk/ru 各 60 场景已执行，但证据片段省略身份、群范围或更正限定，未达来源支持 100% 门槛。英语还发现学位/文凭类型被省略、普通语气偏好被裸词 best 误拦，以及姓名陈述被转成称呼偏好。原输出、分数与失败保留；不增加针对这些输出的 gold alias。

`self-claims-v2.5` 在唯一抽取提示里要求保留完整且安全的自述句、学历中明确的资格类型和级别；称呼字段必须有明确偏好意图。认证凭据仍禁止保存。安全入口只对明确个人适配/学习方式中作为副词的 best 作窄例外，其它人物排名、比较和未来回答指令仍拦截。这些是待真实模型复验的修复，不能由提示文字或单元测试宣称准确率已达标。

## 两条观测路径

已有固定 fixture 回放继续默认 `answer_route=domain`，记录核心记忆答案，便于重现旧报告。受控真实 CLI 默认 `--answer-route public-v1`；选择写入不可变 session manifest，不能改变既有会话的执行源码或路线后继续运行。

`public-v1` 首先调用生产 `MemoryPublicAnswers`。只有它实际返回 False 时才构造生产显式问答上下文，经过 `ExplicitDelivery`、发送前身份/来源检查及持久化 SENT 回执；通用回答的长期记忆、近期正文、profile、向量和旧回复上下文均为空。允许的群业务语气设置仍通过原仓储读取，业务表哈希必须不变。

工具新增 `plain_answer` 与 `plain_answer_audit` 两种调用。前者使用生产 Gemini 文本请求序列化器；后者只接收问题和实际送出的全文，观察是否表达未知、是否作出个人断言。二者都经固定端点、请求白名单、独立逐次预算预留和持久化 usage 账本。模型、身份、成员权限、时间及 Telegram sink 的注入边界明确记录；Moto 与本地域代码仍禁止网络。未覆盖其它供应商 fallback、真实 Telegram 网络及线上并发，不能冒充端到端群验收。

## 语义审阅边界

核心记忆断言来自真实发送回执引用的当前有效事实。通用回答必须实际送达，并保存真实文本；审阅分类中的引用必须是该文本的逐字子串。模糊分类、审阅失败或无引用不能算拒答。服务繁忙提示本身也不算“不知道你的信息”。通用回答中的个人断言一律标为无来源，不能补接 gold 或旧事实使其通过。

自动审阅仍是 **MODEL_OBSERVED**：结构验证只能证明引用存在，不能证明分类在语义上正确，也不能保证列全所有断言。开启试运行前须独立逐条复核通用回答全文及其分类；数值通过与 `model_quality_claim=NOT_VERIFIED / IMPLEMENTED_UNPROVEN` 分开。

## 故障、暂停与恢复

普通网络未知结果保留原预留，只能由生产有界重试取得另一明确记录的响应；账本错误、版本变化或来源失效不能当作可重试网络故障。原 UNKNOWN 请求不会被重复发送，恢复时可复用后来已经保存的成功响应。

真实 HTTP 429 使整个离线会话暂停，不继续耗尽其余场景。预算先落账，当前未完成场景不生成完成文件；全部计划场景继续留在评分分母，报告明确缺失检查点。`execution-status.json` 和最终 provenance 记录当前 RUNNING、PAUSED、FINISHED 或 STOPPED_AFTER_LIMIT 状态；完成运行不保留陈旧的“正在暂停”声明。FINISHED 仅表示所有计划场景已有终结记录，不代表质量通过；外部中断后最后的 RUNNING 记录也不能证明进程仍存活。

操作者确认供应商配额恢复后，显式 `--resume` 才重新创建 broker。恢复只跳过有持久证据的缓存 429 的网络序号，下一次请求使用新序号并重新预留；即使审阅本来只调用一次也可恢复。其它 UNKNOWN、INFLIGHT 或计费错误不适用这个例外。相同旧序号必须匹配原请求哈希，原未知预留不退。

2026-09-15 的旧基线因连续 429 停止：155 个原子提交场景中 152 EXECUTED、3 UNSUPPORTED，85 未提交；252/404 检查点有观测。旧报告文件仅是首场景 smoke，后续汇总须从场景文件另建诊断报告，不能误引用旧 smoke 为全量结果。下一轮采用新源码、新目录和新 manifest，保留原 gold 与十份旧费用账本（含单次配额诊断）。
