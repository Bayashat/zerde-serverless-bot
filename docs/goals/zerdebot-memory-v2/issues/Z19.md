# FIX: 抽奖事务的 DynamoDB 序列化边界

父工单：[Epic #157](https://github.com/Bayashat/zerde-serverless-bot/issues/157)。此项来自执行期间的独立 SDK 故障注入，不替换已批准的产品方向。

## 问题与证据

基线 `2f3abe7` 的 `services/repositories/contest.py` 使用 `table.meta.client`（DynamoDB Resource 已安装自动序列化）又对事务 Key/Item/ExpressionAttributeValues 调用 `TypeSerializer`。两名代理以 boto3 + Moto 独立复现：输入 `{'S':'synthetic'}` 实际 wire 成为 `{'M':{'S':{'S':'synthetic'}}}`，事务因类型错误取消。当前 MagicMock 测试掩盖了 SDK 序列化层问题。未向 AWS 写入真实测试数据。

## 预期行为与接口契约

使用唯一序列化层；事务中的条件检查、写入、outbox 保持原子。创建与规则锚激活、唯一报名、决定落盘、取消、TTL 最终清理必须通过实际 repository + SDK 的模拟语义验证。不得降低条件或改成非事务写入来使测试通过。

## 负责模块与允许修改

`src/bot/services/repositories/contest.py`、相关 contest repository 测试和生命周期文档；仅在需要共享模拟测试依赖时复用 Z12 的 Moto dev 依赖。禁止改变抽奖公平性、权限、中奖选择和业务表结构；不触发真实抽奖/消息/生产写入。

## 依赖、替代路径与恢复

独立代码修复；与 Z12 的 dev 依赖整合。替代重复的手工 AttributeValue 序列化路径。Z11 的业务功能保留验收依赖本修复。回退也必须保留唯一序列化边界，不能回退到双序列化版本。

## 测试、生产验收与退出条件

本地记录成功事务及条件冲突、重投、计数不重复、winner/outbox/TTL 一致性；校验实际 SDK 发送的 AttributeValue 类型。全套 pytest/precommit通过后独立审阅、PR交付。部署读回与 dev 合成业务验证另行记录；现有测试通过不能替代真实 Telegram/生产业务验收。
