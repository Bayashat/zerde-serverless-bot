# FIX: 验证码状态竞争与失败恢复

父工单：https://github.com/Bayashat/zerde-serverless-bot/issues/157

## 目标与问题

正确验证码解限后verified保存失败会被timeout踢；创建/读取故障吞掉会失去恢复任务。

## 已批准契约

challenge generation和条件状态转换；验证/timeout只一个决定生效；决定先持久化，Telegram动作可恢复；NotFound与DB失败区分，旧join/旧timeout不碰新挑战；创建中断有恢复入口。

## 所有权与范围

- Owner：执行本工单的主实现者；共享入口和infra由集成负责人协调。
- 允许：`src/bot/services/handlers/captcha.py`, `src/bot/services/repositories/captcha.py`, `src/bot/services/repositories/sqs.py`, `src/bot/webhook.py`, `tests/test_captcha.py`，及直接相关测试/文档。
- 禁止：不扩大封禁权限，不把成功HTTP200当完成，不移除仍可能在队列中的旧captcha协议而无安全兼容。
- 依赖：无，可在独立写入范围内并行。

## 验证与完成证据

```text
uv run pytest tests/test_captcha.py tests/test_webhook.py tests/test_sqs_task_router.py -q; uv run pytest tests/ -q
```

DB限流/读失败、验证timeout并发、创建投递失败、解限响应丢失、旧timeout重投不误踢不永久限制；模拟与AWS证据分开。

## 替代路径、回滚与状态

按 PLAN 删除/隔离问题路径，不增加同等地位的第二事实或状态来源。每个分支以独立PR交付；代码、部署读回、合成、真实验收分别记录。若缺真实证据，保留 IMPLEMENTED_UNPROVEN，不因单元测试通过关闭产品验收。Memory相关失败只能回无长期记忆问答，不能恢复legacy知识。
